# WPF Testability Task Breakdown

更新日: 2026-03-08

WPF のテスト性改善は変更範囲が広く、1PR で進めるとレビュー負荷が高くなりやすい。  
このため、以下の粒度で段階的に進める。

## Phase 0: Discovery

- [ ] `ViewModel` のうち、WPF 型 (`Dispatcher`, `Window`, `MessageBox` など) へ直接依存する箇所を一覧化
- [ ] `Model` のうち、純粋ロジックとして切り出せる候補を一覧化
- [ ] 現行テスト (`VMagicMirrorTest`) と未カバー領域の対応表を作成
- [ ] 「最初に分離する1機能」を確定

成果物:
- 依存マップ（ファイル単位）
- 最初の対象機能のスコープ定義

## Phase 1: Seam Introduction

- [ ] 対象機能に対する境界インターフェースを追加（実装変更なし）
- [ ] 既存実装を境界経由で呼び出す配線へ置換（振る舞い維持）
- [ ] 置換前後で同一動作を確認する最小回帰テストを追加

PR分割:
- PR-1: インターフェース追加のみ
- PR-2: 呼び出し置換のみ
- PR-3: 回帰テスト追加のみ

## Phase 2: UI-less Extraction

- [ ] 対象機能のロジックを WPF 非依存クラスへ移動
- [ ] 時刻/ファイルI/O/外部プロセス呼び出しを抽象化
- [ ] UI層は入力収集と結果反映に限定

PR分割:
- PR-4: ロジック抽出のみ
- PR-5: 抽象化差し込みのみ
- PR-6: 抽出後のユニットテスト追加のみ

## Phase 3: Test Expansion

- [ ] 正常系ケースのテーブルテスト追加
- [ ] 例外系/境界値ケース追加
- [ ] 回帰バグ再現テストのテンプレート化

PR分割:
- PR-7: 正常系拡張
- PR-8: 異常系拡張
- PR-9: 回帰テンプレート導入

## Execution Rule

- 各PRで変更する責務は1つまで
- 1PRあたりの目安は 300 行差分以下
- `dotnet build` と `dotnet test` を通してからレビュー依頼
